## 3. สิ่งที่เพิ่มในรอบนี้ — AI ฟรีวิเคราะห์ความเสี่ยงประจำวัน + AI ตัวที่ 2 ตรวจซ้ำ + ระบบตรวจ 5 ชั้น

```
 ทุกวัน 08:00 (Apps Script time trigger — ไม่มีคนกด)
        │
        ▼
 ① อ่าน Google Sheets ── Contract_Master · Payment_History · Receipt_Tracking · Accrued
        │
        ▼
 ② สรุป snapshot ── เลยกำหนด / ครบใน 3–7 วัน / ยอดจ่ายไม่ตรง / สัญญาใกล้หมด / Accrued ที่ยังขาด
        │   (โค้ดคำนวณยอดเงินเอง ไม่ให้ AI คำนวณ)
        ▼
 ③ ปิดชื่อคู่ค้า/ทำเลเป็นรหัส V01 / S01 ── ชื่อจริงไม่ถูกส่งออกนอกบริษัท
        │
        ▼
 ④ Gemini API ฟรี (gemini-3.5-flash-lite) ── ตอบ JSON: summary · risks[level] · actions
        │   (มี ANTHROPIC_API_KEY และตั้ง AI_PROVIDER=claude → ใช้ Claude แทนได้)
        ▼
 ⑤ ระบบตรวจคำตอบ 5 ชั้น
        ├─ ชั้น 1 รูปแบบ JSON + ระดับความเสี่ยง ─────── ไม่ผ่าน → ใช้สรุปตามกฎ (INVALID)
        ├─ ชั้น 2 เลขที่สัญญาที่อ้าง ต้องมีจริง ─────── ไม่มี → ตัดทิ้ง
        ├─ ชั้น 3 AI ตัวที่ 2 ตรวจซ้ำ (Claude ถ้ามีคีย์ = ต่างค่าย · ไม่งั้น Gemini 3.8 Flash ฟรี)
        │        ── ข้อที่ผิด → ตัดออก · ระดับไม่ตรงเกณฑ์ → ปรับ · ที่ขาด → เพิ่ม · ให้คะแนน 0–100
        ├─ ชั้น 4 เทียบสรุปตามกฎ ── ความเสี่ยงสูงที่ AI ไม่รายงาน → ระบบเพิ่มให้ (ป้าย "เพิ่มโดยการตรวจ")
        └─ ชั้น 5 ยอดเงินที่ AI เขียน ต้องตรงกับข้อมูล ── ไม่ตรง → แสดง "ตัวเลขตรวจไม่พบ"
        │
        ├──► ⑥ คืนชื่อจริง → บันทึกชีต AI_Insights (พร้อมคอลัมน์ Checks) + Log
        ├──► ⑦ Dashboard แสดงการ์ด "✦ AI สรุปความเสี่ยงประจำวัน" + แถบ "ผลตรวจคำตอบ AI"
        └──► ⑧ มีความเสี่ยงระดับสูง → ส่งอีเมลสรุปให้ผู้ดูแลเอง (MailApp)
```

| ไฟล์ | หน้าที่ |
|---|---|
| `backend/AIInsight.gs` | snapshot · ปิดชื่อ · เรียก Gemini (ฟรี) / Claude · AI ตรวจซ้ำ (`insightReview_`) · ตรวจ 5 ชั้น · สรุปตามกฎ (สำรอง) · บันทึก · อีเมล · API |
| `backend/Alert.gs` | เรียก `dailyAIInsight_()` ใน trigger รายวัน |
| `frontend/js/dashboard.js` | การ์ด AI + แถบผลตรวจ + ปุ่ม **✦ วิเคราะห์ตอนนี้** (admin) |
| ชีต `AI_Insights` | ประวัติทุกรอบ: Status · Provider · Model · Checks · Tokens = หลักฐาน L3.3 / L4.2 / L4.5 |

**สถานะ:** `AI` = AI วิเคราะห์และผ่านการตรวจ · `RULES` = ยังไม่ใส่คีย์ ใช้สรุปตามกฎ · `INVALID` = คำตอบ AI ผิดรูปแบบ · `ERROR` = เรียก AI ไม่สำเร็จ (เช่น เกินโควตาฟรี 429)

**ทำไมเลือก Gemini Free Tier:** ไม่มีค่าใช้จ่าย (ข้อมูลจากหน้า pricing ของ Google: Input/Output "Free of charge") และเรียกครั้งเดียวต่อวันจึงไม่เกินโควตา
⚠️ Free Tier ระบุว่า **"Used to improve our products: Yes"** — ระบบจึงปิดชื่อคู่ค้า/ทำเลก่อนส่งเสมอ (ส่งเฉพาะรหัส เลขที่สัญญา ยอดเงิน วันที่) · ใช้ `generateContent` ซึ่งไม่เก็บบทสนทนาไว้บนเซิร์ฟเวอร์ · แท็บ "ผู้ช่วย AI" (แชตที่ต้องส่งข้อมูลเต็ม) ยังใช้ Claude เท่านั้น

**ทดสอบแล้ว (ก่อน deploy):**
- ไม่มีคีย์ → `RULES`
- Gemini ตอบปกติ → `AI` และไม่มีชื่อคู่ค้า/ทำเลจริงหลุดไปใน request เลย (ผลลัพธ์คืนชื่อจริงถูกต้อง)
- แต่งเลขสัญญา `C-999` → ตัดทิ้ง
- ไม่รายงานงวดครบใน 3 วัน → ระบบเพิ่มให้
- อ้างยอด 77,777.00 ที่ไม่มีจริง → ขึ้นเตือน
- Gemini บล็อก (SAFETY) → `ERROR`
- เกินโควตา (429) → `ERROR`
- ไม่ใช่ JSON → `INVALID`
- มีทั้ง 2 คีย์ → ใช้ Gemini ก่อน · ตั้ง `AI_PROVIDER=claude` → ใช้ Claude
- **AI ตรวจซ้ำ:** ผู้ตรวจตัดข้อที่ AI ตัวแรกอ้างผิด (C-003 ไม่ได้เลยกำหนด/ยอดผิด) · ปรับระดับ C-004 จากสูงเป็นกลาง · เพิ่ม C-002 ที่ขาด และตัดเลขสัญญาที่ผู้ตรวจแต่งเอง (C-777) · มี Claude key → ผู้ตรวจเป็น Claude ต่างค่าย · ผู้ตรวจล่ม (529) / ตอบผิดรูปแบบ → เก็บผลเดิมและแจ้งสถานะ · `REVIEW_PROVIDER=off` → ไม่เรียกผู้ตรวจ
- trigger อัตโนมัติ → ส่งอีเมล · Viewer สั่งรัน → `FORBIDDEN`

## 5. เตรียมตอบคำถามกรรมการ
**ถ้าดึง AI ออก ระบบยังทำงานได้ผลเดิมไหม? (L5.1)**
ระบบหลัก (ทะเบียน, เบิกจ่าย, Accrued, อีเมลแจ้งเตือนดิว) ยังทำงานได้ เพราะ AI เป็นชั้นวิเคราะห์เสริม — ถ้า AI ล่ม ระบบใช้สรุปตามกฎแทนอัตโนมัติ (สถานะ `RULES/ERROR`) · สิ่งที่หายไปคือการสรุปข้ามหลายหมวดเป็นภาษาคนและจัดลำดับสิ่งที่ต้องทำ — จึงตอบตรง ๆ ว่ายังเป็น LV.4 ไม่ใช่ LV.5

**ถ้ารูปแบบ Input เปลี่ยน จุดเชื่อมต่อยังทำงานไหม? (L4.2, L4.4)**
- ระบบอ่านชีตตาม **ชื่อหัวคอลัมน์** ไม่ใช่ตำแหน่ง — แทรก/สลับคอลัมน์ได้
- snapshot ที่ส่งให้ AI สร้างจากโค้ด ไม่ได้ส่งชีตดิบ — AI เห็นรูปแบบเดิมเสมอ
- ถ้า AI ตอบผิดรูปแบบ `validateInsight_` จะปฏิเสธและใช้สรุปตามกฎ · ถ้า Gemini ล่ม/เกินโควตา ก็ใช้สรุปตามกฎ — Workflow ไม่หยุด

**AI ทำอะไร / ไม่ทำอะไร? (L3.3)**
AI ทำ: สรุปภาพรวม, จัดระดับความเสี่ยง, เรียงสิ่งที่ต้องทำ · AI ไม่ทำ: คำนวณยอดเงิน (โค้ดคำนวณแล้วส่งให้), เขียน/ลบข้อมูลในชีต, ตัดสินใจเบิกจ่าย (คนตัดสิน)

**ป้องกัน AI แต่งข้อมูลอย่างไร?**
ตรวจ 5 ชั้นทุกครั้ง: รูปแบบ → เลขสัญญาต้องมีจริง → **AI ตัวที่ 2 (คนละรุ่น/คนละค่าย) ตรวจทุกประโยคเทียบข้อมูลจริง** → ความเสี่ยงสูงที่ AI ไม่รายงาน ระบบเพิ่มให้ → ยอดเงินต้องตรงข้อมูล · ผลตรวจบันทึกในคอลัมน์ Checks และแสดงบนการ์ดให้คนเห็นก่อนตัดสินใจ`n`n**ใช้ AI ฟรี ข้อมูลบริษัทรั่วไหม?**`nส่งเฉพาะตัวเลขสรุป เลขที่สัญญา และวันที่ — ชื่อคู่ค้า/ทำเลถูกแทนด้วยรหัส V01 / S01 ก่อนส่ง แล้วระบบคืนชื่อจริงหลังได้คำตอบ (ทดสอบแล้วว่าไม่มีชื่อจริงหลุดใน request)

**มีใครนำไปใช้ต่อได้ไหม? (L5.4)**
มีคู่มือผู้ใช้ (`USER_MANUAL.md`, ปุ่ม 📖 คู่มือในระบบ), คู่มือติดตั้ง (`SETUP_GUIDE.md`) และโค้ดใน GitHub — ทีมอื่นติดตั้งกับชีตของตัวเองได้โดยตั้ง `SPREADSHEET_ID`
